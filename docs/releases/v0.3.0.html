What's new

0.3.0 also ships everything listed under 0.2.0 in the changelog, which never got a tag of its own.

Instance health, metrics and state

  • A second, loopback-only listener, off until [admin] listen_addr is set. It forwards nothing: it answers questions about this instance.
  • GET /healthz returns 200 ok for as long as the process is serving — unauthenticated, and nothing else.
  • GET /metrics, behind [metrics] enabled = true, serves Prometheus text format. It is written by hand, so no prometheus dependency was added and the lockfile is untouched. When metrics are off the path is a 404, so a scraper can tell "disabled" from "no traffic yet".
  • A management surface, GET /v1/{status,routes,clients,connections,health}, behind a bearer token that the server generates into <config>.admin-token on first start. There is deliberately no token key in the config: a credential in the file you edit, copy and commit is the thing this design avoids. No token means 503, not an open door.
  • nexapipe status reads those same endpoints from the command line (--json for the raw shape), so the running server stays the single source of truth about its own state.
MetricMeaning
nexapipe_connections_total
nexapipe_connections_active		Connections opened since start, and open right now.
nexapipe_connections_by_pathOpen connections by path kind: direct (hole punching succeeded), relayed, unknown. Read from iroh rather than guessed from a socket address, so "nothing to rent" finally becomes a number.
nexapipe_requests_totalRequests answered, by status class.
nexapipe_request_duration_ms_totalMilliseconds answering requests, summed; divide by requests_total for a mean.
nexapipe_l4_flows_totalFinished TCP/UDP flows by protocol and status. Flows are counted separately from requests on purpose: a flow is a tunnel a client holds open as long as it likes.
nexapipe_backends_up
nexapipe_backends_down		Backends in rotation, and backends health checks took out. Read from the live pools at scrape time.
nexapipe_in_flight
nexapipe_build_info		Connections a shutdown waits for; one series identifying the build.

Turning it on

# config.toml
[admin]
listen_addr = "127.0.0.1:9090"

[metrics]
enabled = true

# then
curl -s http://127.0.0.1:9090/healthz
curl -s http://127.0.0.1:9090/metrics | grep connections_by_path
curl -s -H "Authorization: Bearer $(cat config.toml.admin-token)" \
     http://127.0.0.1:9090/v1/status | jq
nexapipe status --json
Loopback only, and there is no escape hatch. A non-loopback bind is refused at startup rather than warned about: the answers name your routes, clients and backends. Reach it from another host over an SSH tunnel, not by widening the address.

Changelog

Added

  • The auxiliary listener and everything above it: /healthz, /metrics, the token-guarded /v1/* endpoints, and nexapipe status.
  • Health checks can be switched off: [health_check] enabled = false, so a backend with no health endpoint is a supported deployment rather than log noise (#47).
  • docs/ROADMAP.md — where NexaPipe stands, what is missing, and the order it gets fixed in (#47).
  • docs/iroh-boundaries.md — what still touches third-party infrastructure whatever relay_mode says. The two READMEs now point at it instead of repeating a caveat, and the iroh version line was corrected in the same pass.
  • CHANGELOG.md, starting with a 0.2.0 entry distilled from the commits since 0.1.1.
  • third_party/smoltcp/PATCHES.md, documenting the patch that third_party/ exists to carry (#48).
  • CodeQL scanning, with its own config (#47).
  • Android: a lint baseline with warningsAsErrors, so a new warning fails CI while a recorded one stays quiet (#48).

Changed

  • Shutdown drains instead of sleeping. It counts the connections both accept loops spawned and waits for them, with a bound so a stuck peer cannot hold the process open (#47).
  • The iroh path in use is logged at startup, including the relay that actually took effect (#47).
  • Release artifact names follow one rule across the server archives, the desktop bundles and the APK: <product>-<version>-<platform>.<ext> (#47).
  • Hardening across the server and the client: stricter config validation, request handling and connection-lifecycle handling, secret scanning, hardened Dockerfiles and per-platform build scripts (#50).

Fixed

  • A single failed health probe emptied a backend pool. failure_threshold was stored and logged but never consulted; it is now the count that takes a backend out of rotation (#47).
  • Android: the credential key is no longer regenerated when the keystore reports an error. On API 26 generating a key under an existing alias deletes that entry first, so one transient failure used to make every stored credential unreadable (#51).

Removed

  • The top-level default_backend. A config that still names it is refused at startup rather than silently ignored. "Send everything here" is now spelled as a catch-all route, host_pattern = "*" (#48).

Before upgrading

Drop default_backend from your config. A config that still has it will not start on 0.3.0 — refusing is the point, since ignoring it would quietly turn forwarding into 404s. Replace it with a catch-all route.
  • Nothing else changes by default: with no [admin] section the auxiliary listener is not bound, and no extra port is held open.
  • [health_check] enabled = false is the replacement if you were carrying a dummy health endpoint on a backend to keep the probe quiet.
  • Desktop: bundles are signed, so an in-app update from 0.2.x verifies as usual through latest.json.
